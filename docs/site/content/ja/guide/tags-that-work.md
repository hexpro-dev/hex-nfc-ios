空のタグのパックに入ったシール、ホテルのカードキー、図書館のラベルは、手に持った感触はどれも同じです。しかし中のチップは同じではなく、タグに保存できる量や、パスワードを設定できるかどうかはチップによって決まります。そもそも iPhone でタグを読み取れるかどうかも、チップで決まります。

自分で使うタグには、NTAG ファミリーの空のタグを購入してください。NTAG213 は 144 バイトを保存でき、Web アドレスや短い連絡先には十分です。NTAG215 は 504 バイト、NTAG216 は 888 バイトを保存でき、長いメモや多数のレコードにはこの容量が必要です。この 3 つはどれもパスワードを設定でき、ロックもできます。空の状態で購入したものではないタグには、たいてい発行元にしか意味のわからないデータが入っています。ホテルのカードキー、交通系カード、ビルの入館証は、どれもそうしたタグです。

手元のタグが何かを知るには、スキャンします。アプリが読み取った内容は「タグ」画面に表示されます。この画面の一番上にあるカードがタグ情報カードで、見出しにはチップ自体の名前が表示されます。スキャンの手順は[タグをスキャンする](scan-a-tag.md)で説明しています。

この名前は型番なので、タグが何に対応しているかを知りたいときは、この名前で検索します。アプリが各チップで何をするかは、チップごとに[チップ対応表](../developer/chip-support-matrix.md)にまとめられています。このページはこのガイドではなく開発者向けドキュメントの一部なので、コマンドやテスト実行について書かれています。

## アプリが表示する名前

タグ情報カードの見出しは、チップ自体の名前です。表示される可能性のある名前は次のとおりです。

:::table[タグ情報カードに表示されるチップ名]
| ファミリー | タグ情報カードに表示される名前 |
| --- | --- |
| NTAG | NTAG 210µ、NTAG213、NTAG213 TT、NTAG215、NTAG216、NTAG424 DNA |
| MIFARE Ultralight | MIFARE Ultralight EV1 (48b)、MIFARE Ultralight EV1 (128b)、MIFARE Ultralight C |
| MIFARE DESFire | MIFARE DESFire、MIFARE DESFire EV1、MIFARE DESFire EV2、MIFARE DESFire EV3 |
| EM Microelectronic | EM V10、EM V11、EM V16 |
| ICODE | ICODE SLIX、ICODE SLIX2 |
| ファミリー名のみ | ISO 15693、FeliCa、電子パスポート、NFC Forum Type 4、ヘルスケア機器 |
:::

最後の行は、チップがファミリーの一員として応答しても、どの型番かを示さない場合に表示される名前です。日本の交通系カードは FeliCa と表示され、専用の結果画面が開きます。詳しくは[交通系カードを読み取る](transit-cards.md)を参照してください。パスポートは「電子パスポート」と表示されます。詳しくは[パスポートを読み取る](passports.md)を参照してください。

NXP 以外のメーカーの Type 4 タグは NFC Forum Type 4 と表示されます。タグとして動作するように設定した Android スマートフォンも同じです。アプリはほかのタグと同じようにそのレコードを読み書きできます。中のチップを特定できないため、カードに**メモリ**の行は表示されず、パスワード、永久ロック、**メモリダンプ**も使えません。ヘルスケア機器は「ヘルスケア機器」と表示されます。詳しくは下の[ヘルスケア機器](#health-devices)を参照してください。

チップによっては、NFC アプリが型番と照合できる情報を何も返しません。その場合、カードには名前の代わりに**報告値**の行と**バージョンバイト**の行が表示されます。これはタグが自分自身について返した内容です。このようなタグでも、通常のタグとして読み取りや書き込みはできます。使えなくなるのは、チップのメモリ配置を知っている必要がある機能すべてです。そのため、パスワード、完全ロック、そして[タグのメモリのコピーを保存する](memory-dump.md)で説明している**メモリダンプ**の操作は使えません。

## カードからわかるチップの情報

チップの概要は 2 つの行にまとめられています。**対応機能**には、「読み取り」「書き込み」「パスワード」「ロック」など、アプリがそのチップでできることが表示されます。「書き込み」は、[タグにリンクを書き込む](write-a-link.md)のように、タグに新しいメッセージを書き込めることを示します。「パスワード」は、タグ自体のパスワードを設定できることを示します。これについては[パスワードでタグを保護する](protect-a-tag.md)で説明しています。「ロック」は、タグを読み取り専用にできることを示します。これはどのタグでも取り消せないため、[タグを完全にロックする](permanent-lock.md)は独立したページになっています。**機能**には、「タップカウンター」や「改ざん検知ループ」など、チップが備えている追加の機能が表示されます。

その下には、チップが応答した場合にだけ表示される行があります。行がない場合は、チップがその項目について何も返さなかったということであり、スキャンに失敗したわけではありません。

**改ざん検知**の行は、改ざん検知ループを備えたチップに表示されます。現在これに該当するのは NTAG213 TT です。ループがつながっている間は「封は未開封」、ループが切れると「開封済み」と表示されます。切れたループは元に戻りません。アプリが開封済みと報告する封は、タグを手にした時点ですでに開いていたものです。スキャンによって封が開いたわけではありません。

**読み取り回数**の行はタップカウンターを備えたチップに表示され、チップが数えた読み取りの回数を示します。「カウンターはオフ」は、行がない場合とは異なります。カウンターは存在するもののオフになっている状態で、ほとんどのタグはこの状態で出荷されます。

**カウンター**の行は、MIFARE Ultralight EV1 で表示されます。2 種類の容量のどちらでも同じです。このチップは独自のカウンターを 3 つ持っており、行には 3 つすべてが 1 行で表示されます。2 つ目の**カウンター**の行に「ティアリング(書き込み中断)を検出」と表示されている場合は、それらのカウンターが正常ではないとチップが報告しています。MIFARE Ultralight C にはどちらの行も表示されません。このチップのカウンターは、アプリが送信しないコマンドに応答するものだからです。

**署名**の行は、チップが 32 バイトの署名で応答した場合は「NXP のオリジナリティ署名」と表示されます。応答がそれより短かった場合は「標準的な NXP 署名ではありません」と表示されます。どちらの表示も、タグが本物かどうかの判定ではありません。アプリはチップが返した内容を記録するだけで、何とも照合しません。

## ヘルスケア機器 {#health-devices}

医療機器の中には、NovoPen 6 や NovoPen Echo Plus といったインスリンペンのように、タグと同じように iPhone に応答するものがあります。Hex NFC は機器が自身について伝える内容からそれを認識し、「タグ」画面の代わりに**ヘルスケア機器**の画面を開きます。名前を特定できるペンでは、見出しが **Novo Nordisk のスマートペン**になります。画面には Hex NFC がペンの投与履歴を読み取らないことが表示され、その下のカードに投与履歴を読み取れるアプリが表示されます。カードには App Store で入手するボタンと、ペンのメーカーが掲載している対応アプリの一覧へのリンクがあります。それ以外のヘルスケア機器では見出しが**ヘルスケア機器**になり、アプリの提案はありません。

Hex NFC が読み取るのは機器が自身について伝える内容だけで、機器に書き込むことはありません。ヘルスケア機器に向けた書き込み、操作、**詳細**のコンソールのコマンドは、何かを書き込んだり送ったりする前に止まります。機器の内容は何も保存されないため、履歴にも表示されません。画面を閉じるには**閉じる**をタップします。

## iPhone で読み取れないもの

よく使われているカードの中に、どの iPhone でも読み取れないものが 1 つあります。MIFARE Classic の場合は、そのことを伝えるメッセージが表示されてスキャンが止まります。タグが故障しているわけではなく、iOS 上のどの NFC アプリでもそれ以上は読み取れません。メッセージとその理由は、[iPhone でこのタグをまったく読み取れないのはなぜ？](troubleshooting.md#tag-not-readable)で説明しています。

MIFARE DESFire のカードにも、程度は軽いものの同じ制限があります。アプリはカードの名前を表示でき、生コマンドを送信することもできます。レコードを読み取れるのはカードに NDEF アプリケーションがある場合で、書き込めるのはそのアプリケーションが書き込みを許している場合です。空の MIFARE DESFire EV1、EV2、EV3 のカードには、**フォーマット**で NDEF アプリケーションを作ることができ、**NDEF 設定を削除**で再び取り除けます。どちらも**操作**画面の**危険な操作**にあります。詳しくは[タグをフォーマットする](erase-or-format.md#format-a-tag)と[カードの NDEF 設定を削除する](erase-or-format.md#remove-ndef-setup)を参照してください。交通系カードや入館証など、すでに別の用途で発行されたカードでは、データが発行元の持つ鍵で保護されています。アプリはそうしたカードを NDEF 用に設定するのを拒否し、そのままにします。

対応しているはずのタグがそれでもスキャンできない場合、原因はたいていチップではなく、タグのかざし方です。[タグをスキャンまたは書き込みできない場合](troubleshooting.md)を参照してください。
