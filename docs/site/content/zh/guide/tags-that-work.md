一包空白贴纸中的一张、一张酒店房卡和一枚图书馆标签，拿在手里感觉都一样。但它们内部的芯片各不相同，芯片决定了标签能存储多少内容、能否设置密码，也决定了 iPhone 究竟能否读取这枚标签。

如果要自己使用标签，请购买 NTAG 系列的空白标签。NTAG213 可存储 144 字节，足够存放一个网址或一条简短的联系人信息。NTAG215 可存储 504 字节，NTAG216 可存储 888 字节，适合较长的备注或多条记录。这三种芯片都可以设置密码，也都可以锁定。不是以空白状态购买的标签，里面通常存满了只有发行方才能解读的数据。酒店房卡、交通卡和门禁卡都属于这类标签。

要知道手中的标签是什么，扫描它即可。应用读取到的内容会在「标签」界面中打开。该界面顶部的卡片就是标签信息卡片，标题是芯片本身的名称。[扫描标签](scan-a-tag.md)介绍了扫描的具体步骤。

这个名称是芯片型号，想了解一枚标签支持什么时，就用它来搜索。应用对每种芯片能做什么，在[芯片支持矩阵](../developer/chip-support-matrix.md)中逐一列出。该页面属于开发者文档，而不是本手册，因此内容涉及命令和测试运行。

## 应用显示的名称

标签信息卡片的标题是芯片本身的名称。它可能显示以下名称。

:::table[标签信息卡片可能显示的芯片名称]
| 系列 | 标签信息卡片上的名称 |
| --- | --- |
| NTAG | NTAG 210µ、NTAG213、NTAG213 TT、NTAG215、NTAG216、NTAG424 DNA |
| MIFARE Ultralight | MIFARE Ultralight EV1 (48b)、MIFARE Ultralight EV1 (128b)、MIFARE Ultralight C |
| MIFARE DESFire | MIFARE DESFire、MIFARE DESFire EV1、MIFARE DESFire EV2、MIFARE DESFire EV3 |
| EM Microelectronic | EM V10、EM V11、EM V16 |
| ICODE | ICODE SLIX、ICODE SLIX2 |
| 仅显示系列名称 | ISO 15693、FeliCa、电子护照、NFC Forum Type 4、健康设备 |
:::

最后一行是芯片表明自己属于某个系列、但不说明具体型号时显示的内容。日本交通卡会显示为 FeliCa，并打开专门的结果界面，详见[读取交通卡](transit-cards.md)。护照会显示为电子护照，详见[读取护照](passports.md)。

非 NXP 制造的 Type 4 标签会显示为 NFC Forum Type 4，设置成模拟标签的 Android 手机也是如此。应用可以像读写其他标签一样读写它的记录。由于无法判断其中是哪种芯片，卡片上没有**内存**一行，也无法为它设置密码、永久锁定或使用**内存转储**。健康设备会显示为健康设备，详见下文的[健康设备](#health-devices)。

有些芯片不提供任何能让 NFC 应用与型号对应的信息。这时卡片上不显示名称，而是显示**报告值**行和**版本字节**行，即标签对自身的描述。这样的标签仍可以像普通标签一样读取和写入，但凡是需要了解芯片内存布局的功能都无法使用。也就是说，无法设置密码、无法永久锁定，也无法使用**内存转储**；[保存标签内存的副本](memory-dump.md)介绍了这项操作。

## 卡片对芯片的说明

有两行概括了芯片的情况。**支持**列出应用能对它执行的操作，例如“读取”“写入”“密码”或“锁定”。“写入”表示标签可以写入新的消息，如[将链接写入标签](write-a-link.md)所述。“密码”表示标签可以设置自己的密码，详见[用密码保护标签](protect-a-tag.md)。“锁定”表示标签可以设为只读。这在任何标签上都无法撤销，因此[永久锁定标签](permanent-lock.md)单独成页。**功能**列出芯片附带的额外功能，例如“读取计数器”或“防拆回路”。

这两行下方的各行，只有在芯片作出相应应答时才会出现。缺少某一行，表示芯片没有提供这方面的信息，绝不表示扫描出了问题。

**防拆**行属于带防拆回路的芯片，目前只有 NTAG213 TT。回路完好时，该行显示“封条完好”；回路断开后，显示“已开封”。断开的回路无法恢复。应用报告为已开封的封条，在你拿到这枚标签时就已经开封了，并不是你的扫描造成的。

**读取次数**行来自带读取计数器的芯片，显示芯片记录的读取次数。“计数器已关闭”与缺少该行不同：它表示计数器存在但已关闭，大多数标签出厂时都是这种状态。

**计数器**行来自 MIFARE Ultralight EV1，两种容量都有这一行。这种芯片有三个自己的计数器，该行在一行中显示全部三个。如果还有第二个**计数器**行显示“检测到写入中断”，表示芯片报告这些计数器的数据不完整。MIFARE Ultralight C 两行都不显示，因为它的计数器只应答特定的命令，而应用不发送这条命令。

当芯片返回 32 字节的签名时，**签名**行显示“NXP 原厂签名”；返回的内容比这短时，显示“不是标准的 NXP 签名”。这两种显示都不能判定标签是否真实。应用只是记下芯片的应答，并不拿它与任何内容进行核对。

## 健康设备 {#health-devices}

有些医疗设备会像标签一样应答 iPhone，例如 NovoPen 6 和 NovoPen Echo Plus 胰岛素笔。Hex NFC 根据设备对自身的描述识别出它，并打开**健康设备**界面，而不是「标签」界面。对于能识别出名称的注射笔，标题显示为 **Novo Nordisk 智能注射笔**。界面会说明 Hex NFC 不读取注射笔的剂量记录，下方的卡片会列出能读取这些记录的应用，附有在 App Store 获取它的按钮，以及指向注射笔制造商的相关应用列表的链接。其他健康设备的标题显示为**健康设备**，不推荐任何应用。

Hex NFC 只读取设备对自身的描述，从不向它写入。针对健康设备的写入、操作或**高级**控制台命令会在写入或发送任何内容之前停止。设备上的任何内容都不会被保存，因此它不会出现在你的历史记录中。点按**关闭**即可离开该界面。

## iPhone 无法读取的标签

有一种常见的卡片，任何 iPhone 都无法读取。遇到 MIFARE Classic 时，扫描会停止，并显示一条提示说明这一点：标签没有故障，iOS 上的任何 NFC 应用都无法进一步读取。[为什么 iPhone 完全无法读取这枚标签？](troubleshooting.md#tag-not-readable)列出了这条提示及其原因。

MIFARE DESFire 卡受到的限制与此相同，只是程度较轻。应用能显示这种卡的名称，也能向它发送原始命令。卡上带有 NDEF 应用时，可以读取其中的记录；这个 NDEF 应用允许写入时，还可以写入记录。空白的 MIFARE DESFire EV1、EV2 或 EV3 卡片可以通过**格式化**获得 NDEF 应用，**移除 NDEF 设置**则会再把它移除。两者都位于**操作**界面的**危险操作**下，详见[格式化标签](erase-or-format.md#format-a-tag)和[移除卡片的 NDEF 设置](erase-or-format.md#remove-ndef-setup)。已经为其他用途发行的卡片，例如交通卡或门禁卡，其数据受密钥保护，密钥由发卡方掌握。应用会拒绝为这类卡片设置 NDEF，并让它保持原样。

如果你认为受支持的标签仍然无法扫描，原因通常在于标签贴近的方式，而不是芯片本身。请参阅[标签无法扫描或写入时](troubleshooting.md)。
